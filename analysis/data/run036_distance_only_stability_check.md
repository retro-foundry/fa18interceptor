# run036 distance-only stability check

Classification: **no-control approach, but not a distance-only LOD probe**.

`run036` has no recorded input events from replay frame 4,152 through 8,821,
which covers the sampled Golden Gate interval.  This confirms the user's
no-control pass; no outside-camera selection or in-game Save event occurred
there.

However, a no-control interval is not by itself a fixed-view direction.  The
exact red `#880000` Golden Gate raster in the forward world viewport moves
substantially while it grows:

| replay frame | red bounds (screen pixels, inclusive) | horizontal midpoint |
| ---: | --- | ---: |
| 4,750 | `274,116`--`347,116` | 310.5 |
| 5,000 | `268,117`--`345,117` | 306.5 |
| 6,000 | `234,120`--`333,121` | 283.5 |
| 7,000 | `158,123`--`331,131` | 244.5 |
| 7,250 | `116,126`--`327,136` | 221.5 |

The midpoint changes by 89 pixels between the first and last samples (and 83
pixels through frame 7,000).  The vertical position and raster orientation
also change as the span enlarges.  Consequently, the view/bearing is changing
enough that a primitive change could be caused by viewing direction or scene
selection rather than range.

This does not weaken the existing renderer result: at frame 7,000 the full
red raster remains directly correlated with `$C35596/$C355CE` line calls.
It only means `run036` cannot promote that result to a distance-controlled
line-to-polygon LOD conclusion.  The requested stable-forward capture remains
the discriminating experiment described in
[`golden_gate_lod_capture_protocol.md`](../golden_gate_lod_capture_protocol.md).
