# Scripted in-flight coverage run013

`captures/run013_scripted/` is a native `E9K_INPUT_V1` replay generated by
`scripts/build_scripted_flight_run.py`. It starts from the compatible,
Engine9000-serialized in-flight state `build/free_flight_600/state.bin`, not
from the menu.

The input stream contains exact Libretro key-down/key-up pairs, spaced 90
frames apart: F1--F10 (`282`--`291`), a repeated F10 after 210 frames, then
H/M/R/T/A/J/G/comma/period/Space/Return. The post-input no-input interval ends
at replay frame 2,520. The stream proves delivery to the core bridge; it does
not by itself prove that every function key reached the game's dispatcher.

The stock Engine9000 core bridge completed the replay in 5.707 seconds. Its
end-state video SHA-256 is
`1318183316cbc7e8d441db74572d26529c2bec029bd8294737fcea084add7eb6`.

The first isolated F1 press does reach `$C1AD74` as raw `$50` and takes the
generic `$C1C23C` queue route, but its consumer translates that byte to zero
and returns without an observed command; see
[`c1ad74_native_f1_queue.md`](routines/c1ad74_native_f1_queue.md). The plain
native F2--F10 events did not reach that breakpoint in the same state. This
scripted stream is not function-key gameplay coverage. The frontend-to-game
mappings remain open and require single-event, no-future-input traces.
