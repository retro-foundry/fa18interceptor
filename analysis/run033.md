# Run033 bridge overflight probe

`run033` is a sealed ordinary replay containing two bridge encounters from a
distance.  The user identifies every red rendered span in its screenshots as
the Golden Gate bridge; the distant red span at frame 5,250 is therefore the
Golden Gate visual anchor.  The following bridge encounter is sampled at a
25-frame cadence in [the dense contact sheet](plots/run033_bridge_dense_contact_sheet.png).
At frame 5,500 its deck and pylons are distant; by frame 6,000 the deck fills
the forward view, and frame 6,250 passes beside a tower.  The coarser whole-run
timeline is retained as [the overflight contact sheet](plots/run033_bridge_overflight_contact_sheet.png).

## Renderer evidence

Three sealed state snapshots were replayed for 64 host frames, with direct
entries to the matrix transform routine `$C1F4AC` recorded before the mutable
workspace is overwritten.

| Replay anchor | Visual band | Transform entries | Distinguishing source inputs |
| --- | --- | ---: | --- |
| 5,250 | red Golden Gate span, distant | 114 | `$C3AD0E` (33), `$C3AF62` (7), `$C3B9B2` (7), `$C3B720` (3) |
| 5,500 | distant approach | 94 | `$C3AD0E` (24), `$C3B720`, `$C3B9B2`, `$C3AF62` |
| 6,000 | deck/tower close | 70 | `$C362A2` (3), `$C36368` (2), `$C3B990` (4) |
| 6,250 | tower passed | 65 | `$C35B56` (7), `$C35B80` (7), `$C3BB2E` (5) |

`$C361E4`, `$C3ACD4`, `$C3B0CE`, and `$C3B588` occur in all three windows.
The two Golden Gate anchors contain the established composed Golden Gate packet
family.  The 5,250 pre-clip collection also selects static control stream
`$C3B6B0` six times.  Its live `$C1F6F8` control-walker inventory also enters
`$C355D0` six times.  A single-step trace from that exact `$C355D0` entry
resolves the first offset to static record `$C358B2` and dispatches handler
`$C212B0`, which copies the selected transformed endpoints from `$C48390` for
a line submission.  The trace later reaches polygon clipping elsewhere in the
same walker run, but this first `$C355D0` record is specifically a line record.
It independently links the red visual identification to the Golden Gate
control-stream family while keeping line and polygon evidence separate.
`$C355D0` remains control data, not an immutable vertex block.

The separate line collector decodes `$C358B2-$C358B7` exactly as `$C212B0`
consumes it: selector `$0001` followed by one terminal offset pair
`$0000,$8006`.  In all six observed `$C355D2` submissions, this selects slots
0 and 1 of the `$C48390` transform workspace and emits one projected segment.
The selected triples vary with the replayed pose, confirming that the six
static bytes are topology/control data rather than coordinates.

`$C362A2`, in contrast, has an earlier trace-proven path to the alternate
`$C36298` bridge-like polygon stream.  This makes run033 positive evidence
that the red Golden Gate span and the subsequent bridge encounter feed
different static renderer components.

It does **not** establish a distance-selected LOD level: the windows are at
different positions and headings, so normal culling can change the input set.
A future LOD claim needs a traced selector that chooses one static source
family over another as measured distance changes for the same bridge instance.
