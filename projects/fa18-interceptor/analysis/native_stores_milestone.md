# Native cockpit stores and complete HUD comparisons

The playable path is `native_frontend_tick` -> `native_flight_tick` ->
`native_hud_draw` -> `native_hud_draw_stores` -> shared `draw_stores_icons`.
C30A00 now executes between weapon status C328A8 and grid readouts C321D2,
using original C309E2/C309EC symbol coordinates, stocks, selection colours,
redraw count and view clipping. The native target links the existing readable
stores owner and host line/pixel rendering; no CPU adapter or chipset is used.

The native wrapper uses the original aircraft/view contract. Original constructors
set stores to $24 or $44; firing decrements them. View offsets are multiples of
16 from C1BAD4, so an in-view centre supplies mask $0800 independently of the
previous glyph pointer. The selection bit determines the last store's colour.
With an offscreen centre, every icon is clipped too; stock counts 0..4 leave
the final colour zero. Source cockpit slide rows are signed bytes, keeping the
centre above row zero. The general shared API retains its inherited-value
parameters; this wrapper is validated for the normal aircraft HUD contract.

Complete HUD caller checks also exposed a shared text error: C32AEE tests the
first digit even with a one-digit field, so an exhausted missile's numeric zero
is blank. `print_bcd_in_view` now reproduces that case. Small-text formatting
retains its separate source contract.

`native_stores_oracle.c` executes full original C30A00 in 1,484 cases and the
complete normal C0F138-C0F2DC HUD range in 280 cases. All non-stack RAM and
drawing planes agree. Fixtures cover every source pan, cockpit slide offsets,
stock combinations 0..4, four weapon kinds, inherited count values, signed
redraw gates, inactive records, update cadence, and independently dirty stores
with weapon text disabled. Fixtures start from an actual disk-backed native
demo checkpoint; original instructions/ROM/chipset are validation-only.
